# SUITE ONE — Verified Private Matching

신원과 프로필을 확인한 회원에게 제한된 소개를 제공하는 프라이빗 매칭 서비스입니다.

> 현재 SUITE ONE은 기획 및 MVP 개발 단계입니다.  
> PRD에 포함된 문제 정의, 운영정책, 가격과 성공지표 중 일부는 아직 검증되지 않은 가설입니다.

## Product Vision

SUITE ONE은 무제한 프로필 탐색 대신, 검증된 회원에게 제한된 후보를 두 가지 방식으로 소개합니다. 양측이 복수 후보를 동시에 확인하는 `동시 상호 선택`과 여성이 먼저 남성 프로필을 확인하는 `사전 스크리닝`을 운영 상황에 맞게 함께 사용합니다.

가입 심사, 제한적인 프로필 공개, 소개 수락, 일정 및 장소 조율 과정을 하나의 서비스 안에서 제공하여 더욱 신뢰할 수 있고 집중도 높은 만남 경험을 만들고자 합니다.

## Current Problem Hypotheses

현재 다음 문제들이 존재할 수 있다고 가정하고 있습니다.

- 많은 프로필을 반복해서 탐색하는 과정에서 피로를 느낄 수 있습니다.
- 상대방의 신원과 프로필 정보가 사실인지 판단하기 어렵습니다.
- 사진과 개인정보가 불특정 다수에게 노출될 수 있습니다.
- 상호 호감 이후 일정과 장소를 조율하는 과정이 번거롭습니다.
- 심사, 소개, 취소 및 환불 기준이 불명확하면 유료 서비스에 대한 신뢰가 낮아질 수 있습니다.

이 문제들은 아직 실제 사용자 조사를 통해 검증되지 않았습니다. 잠재 사용자 인터뷰와 비공개 베타를 통해 확인할 예정입니다.

## MVP Flow

1. 계정 생성 및 휴대전화 본인인증
2. 프로필과 선호조건 작성
3. 사진과 인증자료 제출
4. 관리자 가입 심사
5. 승인 회원에게 매칭 방식에 따른 제한된 후보 소개
6. 동시 상호 선택 또는 여성 우선 사전 스크리닝
7. 상호 수락 후 일정과 장소 조율
8. 만남 확정 및 알림
9. 참석 확인, 피드백 및 신고 처리

## Core Principles

- 동시 상호 선택과 사전 스크리닝을 함께 운영합니다.
- 프로필은 필요한 상대에게 제한적으로 공개합니다.
- 상대 회원에게 원본 인증자료를 공개하지 않습니다.
- 운영 심사를 통해 여성 매력회원을 별도로 분류하고 우선 소개 여부를 선택할 수 있게 합니다.
- 일반회원은 만남 티켓 1장, 매력회원은 만남 티켓 2장을 사용합니다.
- 결혼, 연애 또는 실제 만남의 성공을 보장하지 않습니다.
- 민감한 심사와 신고·분쟁에는 관리자가 개입합니다.

## Matching Modes

SUITE ONE은 한 가지 소개 방식만 사용하지 않습니다.

- `동시 상호 선택`: 남녀 양측에게 제한된 복수 후보를 동시에 제공하고, 서로 선택한 조합만 매칭합니다. 회차가 끝나기 전에는 상대의 선택 여부를 공개하지 않습니다.
- `사전 스크리닝`: 여성에게 선정된 남성 프로필을 먼저 제공하고, 여성이 수락한 경우에만 해당 여성의 프로필을 남성에게 전달합니다.

두 방식은 회원 선호, 후보 구성과 운영 상황에 따라 함께 사용합니다. 전체 회원 검색이나 무제한 스와이프는 제공하지 않습니다.

## Attractive Member Policy

운영 심사를 통해 외모와 전반적인 매력이 뛰어난 일부 여성 회원을 `매력회원`으로 분류합니다. 회원은 `골고루 소개`, `매력회원 우선`, `일반회원 우선` 중 원하는 소개 방향을 설정할 수 있습니다.

- 일반회원과 매력회원 모두 소개 또는 동시 선택 참여 시 소개 티켓 1장
- 일반회원과 만남 확정 시 만남 티켓 1장
- 매력회원과 만남 확정 시 만남 티켓 2장

회원 유형과 예상 티켓 차감량은 선택 또는 수락 전에 안내합니다. 세부 선정 기준과 이의제기 절차는 출시 전 운영·법률 검토를 거쳐 확정합니다.

## Decisions Under Review

다음 사항은 아직 최종 결정되지 않았습니다.

- 핵심 사용자의 연령대와 관계 목적
- 이성 간 매칭으로 MVP를 제한할지 여부
- 동시 상호 선택에서 한 회차에 제공할 후보 수
- 두 매칭 방식의 배정 비율과 운영자 전환 기준
- 여성 승인 후 실제 화면을 확인한 뒤 보완할 여성 전용 흐름
- 가입 승인·대기·반려의 객관적인 기준
- 성별에 따라 서로 다른 인증 기준을 적용할지 여부
- 소개·만남 티켓 가격과 차감 시점
- 메시지 기능의 제공 범위
- 본인인증·지도·문자·파일 저장 업체
- 개인정보와 결제정책에 대한 법률 검토 방법

## Proposed Technology Stack

기술 구성 역시 MVP 개발 과정에서 변경될 수 있습니다.

- Mobile: Flutter
- Backend API: Django REST Framework
- Admin: Django Admin
- Database: PostgreSQL
- File Storage: Private object storage
- Push Notifications: Firebase Cloud Messaging
- Error Tracking: Sentry
- CI/CD: GitHub Actions
